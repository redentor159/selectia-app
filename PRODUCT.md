# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users
Software architects, tech leads, and developers who need to choose the best Large Language Model (LLM) for their projects. They are highly technical, data-driven, and value transparency, latency, cost, and benchmark accuracy.

## Product Purpose
SelectIA is a comparison dashboard and interactive directory for LLMs. It aggregates real-time data from HuggingFace, Artificial Analysis, and BenchLM to provide a multidimensional view of model performance, cost, adoption, and API availability. Success means a user can confidently pick a model based on hard data rather than marketing claims.

## Positioning
Unlike static tier lists or single-benchmark leaderboards, SelectIA merges API pricing, live ecosystem adoption (HuggingFace Spaces), and rigorous multidimensional benchmarks (BenchLM + AA) into a single unified dashboard with interactive charts (Elo vs Cost, Adoption vs Quality).

## Operating Context
Users evaluate models while architecting a system or planning a migration. They compare Context Window size, TTFT (Time To First Token), and raw Intelligence (Elo) side-by-side to find the optimal ROI for their specific use case.

## Capabilities and Constraints
- Pulls live data from multiple APIs (HuggingFace, BenchLM, Artificial Analysis).
- Uses a dark-mode first, data-heavy dashboard interface.
- Heavy use of charts (Recharts) and structured data tables.

## Brand Commitments
- Name: SelectIA.
- Voice: Technical, authoritative, neutral, data-first.
- The interface must feel premium, dense with information but not overwhelming, respecting the user's intelligence.

## Evidence on Hand
- Real data fetched from APIs.
- Real model names, provider badges, and token pricing.

## Product Principles
1. **Data over opinion:** Let the charts and benchmarks speak.
2. **Dense but scannable:** Architects want maximum data density without cognitive overload.
3. **Compare, don't prescribe:** Show the tradeoffs between cost, speed, and intelligence so the user decides.

## Accessibility & Inclusion
Must support high contrast for data visualization charts to ensure readability of complex graphs.
